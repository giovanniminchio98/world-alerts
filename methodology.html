Methodology

How data gets onto this map, how a place is matched against it, and what the results can and cannot tell you.

What counts as an incident

An “incident” is a record published by one of the connected sources:

  • Earthquakes — every event in the USGS “all earthquakes, past 7 days” feed (including small events and some non-earthquake seismic events such as quarry blasts, which are labelled).
  • Major disasters — events in the GDACS alert list (earthquakes, tropical cyclones, floods, volcanoes, droughts, wildfires) with the GDACS alert level as published.
  • Natural events — open events in NASA EONET (wildfires, severe storms, volcanoes, floods, landslides, drought, dust, snow, temperature extremes), curated from other agencies. EONET gives no severity level, so these are never counted as high severity; storms are shown at their latest reported position with their path.
  • Weather alerts — active U.S. National Weather Service watches, warnings, advisories and statements (United States and territories only).
  • Satellite thermal detections — NASA FIRMS active-fire / thermal hotspot detections. These are counted separately and are not called incidents, because a detection can be a wildfire, agricultural burning, an industrial heat source, a gas flare or another hot surface.

The project never invents a severity score. Colours map only values the source supplies: earthquake magnitude, the GDACS alert level (Green / Orange / Red) and NWS severity (Minor → Extreme). Severity is always also shown as text, size or an icon, not by colour alone.

Time window. Disaster alerts and natural events are shown only if the source reports them active inside the selected window: an event whose latest episode ended, or that was last updated, before the window began is hidden, even if the feed still lists it.

Colours and textures on the map show the hazard type (blue for floods, purple wind streaks for storms, orange for wildfires, red for volcanoes, gold for drought, brown for earthquakes). Severity is shown separately: by the GDACS alert-level ring, magnitude, or NWS severity colour.

“High severity” in the location summary means: earthquake magnitude 5.0 or above, a GDACS Orange or Red alert, or an NWS alert with severity Severe or Extreme.

How data is collected and normalised

  1. A GitHub Actions workflow runs on a schedule (approximately every 15 minutes) and decides which sources are due: USGS ≈ every 15 min, NWS ≈ 15 min, GDACS ≈ 30 min, FIRMS ≈ 60 min.
  2. Each due source is fetched with timeouts, retries and an identifying User-Agent. Keys (for example an optional NASA FIRMS MAP_KEY) exist only as GitHub Actions secrets and are never sent to browsers.
  3. Responses are converted to one common incident schema (title, category, severity, geometry, event time, source-update time, fetch time, countries, attributes, caveats, source link) and validated.
  4. If a fetch or validation fails, the previous valid data is kept and only the failed attempt is recorded. An error never replaces a known valid feed with an empty list.
  5. Static JSON / GeoJSON files and a manifest of source statuses are published with the site on GitHub Pages. Your browser downloads these files; there is no server or database.

Satellite thermal detections are too numerous for one file, so they are published as 10° × 10° tiles plus a 1° summary grid. The map shows the grid at world and continental zoom and loads individual detections only for the area you are viewing or have selected.

Event time, fetch time and publish time

Source event timeWhen the event happened or the alert was issued, as stated by the source. Sources may publish minutes to hours after this.
Last fetched by this projectWhen the refresh workflow last successfully downloaded the source.
Last published updateWhen the static data files were generated and published to the website.

All times are stored in UTC and shown in your local time zone by default (switch to UTC under Display in the layers panel).

GitHub Actions scheduling delays

Data refreshes are scheduled through GitHub Actions. Scheduled workflows are not guaranteed to start at the configured minute; they can run late — sometimes much later — especially when GitHub Actions is under heavy load, and occasionally a scheduled run is skipped. That is why this site shows actual timestamps from the published metadata instead of assuming a fixed schedule, and never claims to be real-time.

How location-radius matching works

  • Point incidents (earthquakes, thermal detections, GDACS earthquakes and volcanoes): distance from the selected point is computed with the Haversine great-circle formula (Earth radius 6,371 km). Events within the selected radius (25–500 km, default 100 km) and time window are listed with their distance and compass direction. Distance is a spatial aid only — it is not proof that an event affects a place.
  • Area alerts (NWS polygons and zones, GDACS affected areas): the location is matched when it lies inside the published geometry. GDACS areas whose boundary is within the radius are listed as “boundary about X km away (approximate)”.
  • Representative locations: many GDACS floods, droughts and cyclones are published with a single representative coordinate. These are labelled “Representative event location — affected area may be broader” and are never presented as precise city pins.
  • Country-level matches: when GDACS lists the location's country as affected, the event is shown as a country-level match with no fake distance.
  • For clicked points, the country is estimated offline from Natural Earth outlines (approximate near borders and coasts).

Why “no matching incident” does not mean “safe”

An empty result means only: No matching incidents were detected by the connected sources for this area and selected time window. It does not confirm that no disruption exists.

Sources cover only some hazard types, have detection thresholds, publish with delays, can revise or remove events, and may be temporarily unavailable. Many hazards — local flooding, crime, conflict, industrial accidents, power or Internet outages, transport disruption, health threats — are not covered at all. This site therefore never describes a place as “safe”, “normal” or “without danger”.

How stale-data labels work

  • Updated — the latest successful fetch is within the source's expected interval plus a grace period (USGS 45 min, GDACS 90 min, FIRMS 180 min, NWS 90 min).
  • Stale — no successful fetch within that threshold (for example because scheduled runs were delayed). Data is still shown, with its age.
  • Refresh failed — the latest attempt failed and there is no recent valid data. The last valid data, if any, is still shown with its timestamp.
  • Not connected / coverage unavailable — the source is not implemented, or does not cover the selected location (e.g. NWS outside the United States).

Status is recalculated in your browser using the current time, so a page left open will show data ageing into “stale” if no new update is published. The page also checks for newly published data every 10 minutes.

Why blackouts and Internet layers have limited coverage

There is no single free, standardised, reliable global real-time feed of electricity outages: outage information is spread across thousands of utilities, grid operators and municipal dashboards, each with its own format and terms. Power outages are therefore designed as a regional provider plugin system that will only show data where an official structured feed is connected — and otherwise says “No electricity-outage data source is currently connected for this location.”

Internet-disruption data (for example Cloudflare Radar) requires an API token that must not be exposed in browser code, has licence and redistribution conditions, and is usually country-, region- or network-level rather than city-specific. It is not connected by default. Airport/airspace status and public-health notices are likewise planned but not connected.

Emergency numbers and offline use

The location card lists emergency telephone numbers for the selected country, compiled from Wikipedia's list of emergency telephone numbers. They are community-compiled, can be incomplete or out of date, and are shown with a note to confirm locally.

The site can be installed and used offline. Offline, it shows only what this device already downloaded — the latest published data it saw (with its original timestamps and stale labels), map areas you viewed or saved, and the emergency-number list. Nothing updates until you reconnect.

Data-use limitations

Each source's attribution and licence notes are on the sources page. Data is provided as published by the sources, may be revised, and may contain errors introduced by the source or by this project's processing.

This website aggregates third-party public data and may be delayed, incomplete, inaccurate, or unavailable. It is not an emergency warning system and must not be used as a substitute for official local authorities, emergency services, or safety instructions.
